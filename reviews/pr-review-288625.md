### Context / Motivation

Prettier 2.8.8 is end of life and ran inside ESLint as the `prettier/prettier` rule. A full `prettier --check` took about 7.5 min, while `node scripts/oxfmt --check` takes about 6 s. oxfmt comes from the same oxc project as the `oxlint` Kibana already uses, and matches Prettier 3.8 output on 99.6% of files. Part of [elastic/apps-dx#233](https://github.com/elastic/apps-dx/issues/233); closes [elastic/apps-dx#244](https://github.com/elastic/apps-dx/issues/244).

> With formatting gone, ESLint has no rules left, so this removes it: `scripts/eslint`, the `.eslintrc` files and `@kbn/eslint-config` are gone […] The `kbn-eslint-plugin-*` packages and `eslint-disable` comments stay, since oxlint uses them.

> `scripts/lint`, the precommit hook and `check.js` don't run oxfmt yet, and `.git-blame-ignore-revs` comes after merge.

I checked the "no rules left" claim against `upstream/main`. `packages/kbn-eslint-config/{javascript,typescript,jest,react}.js` only set parsers and plugins, and every rule that's left is either `'off'` or comes from `eslint-config-prettier`. The only real rule was `prettier/prettier`. So removing ESLint doesn't drop any lint coverage.

### Summary

For your team, what changes is the **OpenAPI codegen post-process**. It used to run `npx prettier --write`, then `scripts/eslint --fix` (which ran oxlint fixes first, then ESLint). Now it runs oxfmt, then `scripts/lint --fix` twice, then oxfmt again. Everything else your team owns is generated reformatting with no behaviour change: trailing commas in type parameters, `as X` casts moved outside the parentheses (`}) as X`), and long template literals kept on one line. That last one is why the `*.gen.ts` path lines got longer. The PR description matches the diff.

### Files touched

- **Codegen pipeline (`kbn-openapi-generator`):** `format_output.ts` swaps `npx prettier` for `runOxfmt()` from the new `@kbn/oxfmt` package, using a path relative to the repo root because oxfmt only expands globs relative to its cwd. `fix_lint.ts` (renamed from `fix_eslint.ts`) calls `scripts/lint --fix` twice; the first pass is `reject: false`. `openapi_generator.ts` merges the bundle and non-bundle branches into one `target` and runs format → lint fix → format.
- **Dependency wiring:** `tsconfig.json` and `moon.yml` add `@kbn/oxfmt`.
- **Generated clients:** `test-api-clients/scout/*.gen.ts` regenerated by kibanamachine with the new pipeline. Formatting only.
- **Bulk reformat:** ~166 detection engine, lists, exceptions, alerting-gaps and `kbn-securitysolution-*` files. I checked every non-whitespace diff line in your files (`git diff -w`, grouped by line) and they're all Prettier‑3‑style layout changes. Nothing changes meaning.

### Flow trace

`pnpm openapi:generate` in `security_solution` (CI: `.buildkite/scripts/steps/code_generation/security_solution_codegen.sh`):

1. `generate(config)` in `openapi_generator.ts` writes the raw `*.gen.ts` output from the Handlebars templates.
2. `target = bundle ? bundle.outFile : resolve(rootDir, './**/*.gen.ts')`.
3. `formatOutput(target)` → `runOxfmt([relative(REPO_ROOT, target)])` → `node <oxfmt bin> --config .oxfmtrc.json <glob>` with `cwd: REPO_ROOT`. oxfmt applies `.oxfmtrc.json` `ignorePatterns` plus `.gitignore`.
4. `fixLint(target)` → `globby` expands the files (returns early if there are none), then runs `node scripts/lint --fix <files>` with `IS_KIBANA_PRECOMIT_HOOK=1`. The first pass ignores the exit code, because oxlint applies one fix per pass and skips overlapping ones (e.g. swapping the license header). The second pass throws if errors are still left.
5. `formatOutput(target)` runs again, because oxlint's fixes don't respect formatting.
6. CI's `check_for_changed_files "pnpm openapi:generate"` fails or auto-commits if the output differs from what's committed. `kibana-ci` is green on the head commit `b9dd9a9a`, so the new pipeline gives stable output for every security codegen target.

### Assumptions

- The generator's `rootDir` is inside `REPO_ROOT`. If it weren't, `relative()` would produce a `../…` glob, which oxfmt (cwd = repo root) would probably ignore or reject.
- Two oxlint passes are enough to settle every fix the templates need. If a future template change needs three, generation fails loudly on the second pass instead of leaving bad output, which is the safer way to fail.
- `oxfmt@0.66.0` stays pinned. It's pre-1.0, so a version bump could reformat every `*.gen.ts` file and send a pile of codegen churn through the CI auto-commit.
- `*.gen.ts` files aren't covered by `.oxfmtrc.json` `ignorePatterns` or `.gitignore`. I checked: they aren't, so they do get formatted.

### How to test

CI already covers the main case: `kibana-ci` is green, and its codegen step reruns `pnpm openapi:generate` and fails if the output changes. These steps cover the edges CI doesn't hit.

1. **Bootstrap on the branch.** `oxfmt` isn't in `node_modules` on main, so run `node scripts/kbn bootstrap` first. Bootstrap again when switching back to main.
2. **Regenerate everything from scratch.** A plain `pnpm openapi:generate` mostly rewrites files that are already correct. Deleting the output first makes the whole pipeline (oxfmt, lint fix twice, oxfmt again) do real work:
   ```bash
   cd x-pack/solutions/security/plugins/security_solution
   find . -name '*.gen.ts' -not -path '*/node_modules/*' -delete
   pnpm openapi:generate
   git status   # expect clean
   ```
   Do the same for `kbn-securitysolution-lists-common`, `exceptions-common` and `endpoint-exceptions-common`. They're listed in `.buildkite/scripts/steps/code_generation/security_solution_codegen.sh`.
3. **Run it from a Cursor or VSCode terminal.** `fix_lint.ts` sets `IS_KIBANA_PRECOMIT_HOOK=1` so that unused imports get removed even when the editor environment variables are set. That's easy to break and CI never runs inside an editor.
4. **Make a real schema change.** Add a field to a detection engine OpenAPI YAML and regenerate. Then check:
   - the output is formatted (`node scripts/oxfmt --check <file>`)
   - lint passes (`node scripts/lint <file>`)
   - the license header is correct and there are no leftover unused imports

   This covers the two-pass lint fix, which only matters when the templates produce something messy.
5. **Bundle path.** `openapi_generator.ts` now handles the `bundle` and glob cases with one code path. `bundle` is used by `security_solution/scripts/openapi/generate.js` and `kbn-securitysolution-exceptions-common/scripts/openapi_generate.js` (they produce the `test-api-clients` scout and supertest clients). Both run in CI's codegen step, so the regenerate-from-scratch step above covers them too. Also delete `x-pack/solutions/security/packages/test-api-clients/**/*.gen.ts` before regenerating.
6. **Jest inline snapshots.** Pick a team test that uses `toMatchInlineSnapshot`, break the snapshot, run `node scripts/jest <file> -u`, then run `node scripts/oxfmt --check <file>`. This goes through the new custom Prettier shim in `kbn-jest` (`src/oxfmt_prettier.js`), which spawns oxfmt for each write.
7. **Backports (main worry for the team).** Release branches still use Prettier 2, so backporting a change to any of the 173 reformatted files will likely hit conflicts in the reformatted code. For `*.gen.ts` files, the fix is to regenerate on the target branch rather than cherry-pick. Can't really be tested before merge, so ask the author whether ops has a plan.

### Follow-up Review Activities

1. **Old vs new codegen post-process: why two lint passes and a second format.** I read `src/dev/run_eslint.js` and `src/dev/oxlint/lint_files.ts` on `upstream/main` and compared them with `packages/kbn-lint-cli/run_lint_cli.ts` on the branch. The new pipeline has the same steps as the old one, but makes two hidden ones explicit, and the fix loop is shorter.
   - Old `scripts/eslint --fix` ran oxlint fixes via `fixUntilStable()` (reruns `oxlint --fix` until the file stops changing, `MAX_FIX_PASSES = 10`), then ESLint `--fix`. ESLint's only active rule was `prettier/prettier`, so it quietly reformatted after oxlint's edits.
   - New `scripts/lint --fix` runs oxlint once, with no until-stable loop. The PR hard-codes two passes because oxlint skips overlapping fixes (adding the license header while removing the template's one), and adds a second `formatOutput()` to replace the reformat ESLint used to do.
   - `fixUntilStable()` still exists on the branch (`src/dev/oxlint/lint_files.ts`), but only the precommit hook and `check.js` (`run_oxlint_contract.ts`) use it.
   - Effect: same output today (`kibana-ci` codegen green), but up to 10 passes became 2. A template that needs three passes would make `pnpm openapi:generate` fail on the second pass. `reject: false` on the first pass also hides real oxlint crashes until the second pass hits the same error.
   - Both old and new `--fix` use the errors-only oxlint config, so the set of fixes applied hasn't changed.
